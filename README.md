### Разметка документов

Если вдруг всё заработало, то можно проводить разметку данных.
Все данные о вопросах и разметке находятся в файле evidence_regions_service/data/samples.json. Туда же сохраняются вносимые изменения. Любой файл с разметкой можно поместить по этому адресу, и он будет загружен в приложение при запуске.

Вверху страницы находятся 3 кнопки: документ, вопрос, просмотр документа:
1. Кнопка "документ" открывает вкладку выбора документа, с которым ведётся работа (его нужно выбрать сначала).
2. Кнопка "вопрос" открывает вкладку выбора вопросов. Если не выбрать ни один вопрос, нельзя будет производить разметку (невероятно), поэтому выбираем вопрос
3. Кнопка "просмотр документа" открывает вкладку работы со всеми регионами. Там происходит просмотр документов, регионов, добавление пользовательских регионов и сохранение разметки.

![document_annotation_UI](/images/UI_image.png)

1. Переключение страниц в документе.
2. Область работы со своими регионами. Карандаш -вкл/выкл режима рисования своих регионов. Помойное ведро - удаление своих регионов (в обратном порядке их добавления). Цветной  квадрат - смена цвета, которая не работает. В режиме рисования своих регионов их нельзя выделять, так что сначала нужно войти в режим рисования, нарисовать регион, выйти из режима рисования, а уже потом выделить нарисованный регион. Нарисованные регионы не сохраняются если их не сохранить (внезапно).
3. Переключение между вопросами к документу. Убедитесь, что сохранили все нарисованные вами регионы, перед тем, как переходить к следующему вопросу.
4. Сохранение всех выделенных аннотированных регионов для текущего вопроса.
5. Список выделенных регионов для текущего вопроса с типами.
6. Документ с регионами. Регионы кликабельные. Иногда регионы не отображаются, если не поводить курсором по странице.

### А чё делать-то?

MinerU разбивает документы на регионы, Graph-M-RAG должен находить регионы с релевантной информацией и генерировать адекватные ответы на их основе. Наша задача - отметить те регионы, в которых содержаться релевантные для каждого вопроса данные. В папке cut_samples_files содержатся нарезанные фрагменты оригинального файла, качайте свой.
Упрощённый алгоритм следующий:
1. Выбираем документ
2. Выбираем вопрос
3. (опционально) вникаем в вопрос и в то, какие данные могут понадобиться для ответа на него
4. находим и выделяем (т.е. прокликиваем) все регионы, в которых содержатся данные для ответа на текущий вопрос
5. (опционально) дорисовываем свои регионы, если имеющихся регионов недостаточно, или есть какие-то мысли. Добавление пользовательских регионов должно быть обосновано в письменном файле (потом наберём материала для статьи из этого) https://docs.google.com/document/d/1a4gRBCsweWo4u3v3QFlvnQJT1IV75ZD4qksCiko6qDo/edit?usp=sharing
6. Сохраняем регионы
7. Переходим к следующему вопросу

### Нюансы разметки
1. На странице отображаются bbox-ы регионов. При этом minerU иногда объединяет несколько регионов в один (например, 2 части одного абзаца на разных страницах), но bbox выставляет только по одному региону, поэтому иногда некоторые регионы не имеют выделенных bbox-ов, хотя их содержимое в базе присутствует.
2. Подписи к изображениям и таблицам привязаны к родительским изображениям и таблицам, а их bbox перезаписывается как bbox родительского элемента, поэтому у этих подписей нет выделения региона на странице в просмотре документа. На самом деле он есть, просто он совпадает с bbox-ом изображения. Иногда bbox подписи находится выше bbox-а родительского элемента - тогда выделенный элемент будет обладать типом "прочее".
3. По задумке, на вопросы, которые Not answerable нет свидетельств, но иногда по логике они есть (например, если вопрос задаётся по несуществующему столбцу в существующей таблице, эта таблица может быть убедительным подтверждением "неотвечаемости" вопроса), возможно там тоже стоит смотреть.
4. Файл samples.json уже частично размечен вручную и через сравнение с датасетом MMDocIR.
